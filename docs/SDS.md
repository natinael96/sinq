# Software Design Specification (SDS)
### Ge'ez Hours of Prayer — "ጸሎት" (Tselot) Android Application
Version 1.0 · Companion to `docs/SRS.md`

---

## 1. Introduction

### 1.1 Purpose
Describes the architecture and detailed design that satisfies the requirements in
`docs/SRS.md`, with emphasis on the new **Habit-Streak** module.

### 1.2 Scope
Covers system architecture, technology stack, data design, persistence, component
design per feature, UI/navigation design, and the detailed design of the
habit-tracking/streak/heatmap module. Build and verification are included.

### 1.3 Design Goals & Principles
- **Offline-first, zero data collection** (no network permission).
- **Content is data**: bundled JSON generated by an offline pipeline; never mutated at runtime.
- **Non-destructive personalization**: user overlays keyed by stable IDs.
- **Small, boring architecture**: single module, repository-backed Compose state, no ceremony.
- **Compiler-enforced correctness**: exhaustive `when`, complete string tables, typed models.

## 2. System Architecture

### 2.1 Architectural Style
A single-module, single-Activity **Jetpack Compose** app using a lightweight,
unidirectional, repository-backed pattern (no heavyweight ViewModel layer):

```
        ┌─────────────────────────────────────────────┐
        │            UI (Jetpack Compose)             │  screens + composables
        │  reads state via collectAsState/produceState │
        └───────────────▲──────────────┬──────────────┘
                        │ Flows        │ suspend calls
        ┌───────────────┴──────────────▼──────────────┐
        │                Repositories                 │  stateless `object`s
        │  Content · Settings · UserData · Highlight   │
        │  Layout · Hours · Modes · Habits            │
        └───────────────▲──────────────┬──────────────┘
                        │              │
        ┌───────────────┴───┐   ┌──────▼───────────────┐
        │  Bundled assets   │   │  Jetpack DataStore    │
        │  (JSON content)   │   │  (Preferences, JSON)  │
        └───────────────────┘   └──────────────────────┘

        Reminders subsystem (Android framework):
        AlarmManager → AlarmReceiver → AlarmService (foreground) → AlarmActivity
        SystemEventsReceiver (boot/update/time-change → reschedule)
```

- **UI layer** — Compose screens read repository `Flow`s via `collectAsState` and one-shot loads via `produceState`; they call `suspend` repository mutators inside `rememberCoroutineScope().launch`. No ViewModels; screen state is local Compose state.
- **Repository layer** — Kotlin `object` singletons; each owns one DataStore file and (de)serializes a JSON blob via kotlinx.serialization. Pure helper functions (merges, streak math) live here or beside the models for testability.
- **Content layer** — read-only JSON assets loaded once and cached in memory.
- **Reminders subsystem** — framework components (receivers, a foreground service, a full-screen activity) driven by the active mode in DataStore.

### 2.2 Technology Stack
- **Language**: Kotlin 2.1; **UI**: Jetpack Compose + Material 3, Navigation-Compose, `material-icons-extended`.
- **Persistence**: Jetpack DataStore (Preferences); **serialization**: kotlinx.serialization (JSON).
- **Scheduling**: `AlarmManager.setAlarmClock` (with inexact fallback); foreground `Service`; `RingtoneManager`/`MediaPlayer`; `Vibrator`.
- **Build**: Gradle (Kotlin DSL) + version catalog; `minSdk 26`, `targetSdk 36`; JUnit4 unit tests.
- **Assets**: Abyssinica SIL (reading), Noto Sans Ethiopic (UI) — OFL 1.1; content JSON.
- **Content tooling**: `tools/extract_content.py` generates assets from the 80-weahadu Amharic Bible + `content/hour_mapping.json`.

### 2.3 Package Structure
```
com.agpeya.app
├─ MainActivity.kt                 // single Activity, NavHost, theme+language provider, deep links
├─ model/Models.kt                 // @Serializable data models
├─ data/                           // repositories (one DataStore each)
│   ├─ ContentRepository           // bundled hours + Psalter (in-memory cache)
│   ├─ SettingsRepository          // theme, language, font, reading mode, alarm prefs, onboarded
│   ├─ UserDataRepository          // bookmarks, recents, scroll positions
│   ├─ HighlightRepository         // verse → color
│   ├─ LayoutRepository (+PrayerLayout) // per-hour order/hidden/added psalms
│   ├─ HoursRepository             // custom hours, order, hidden, name overrides
│   ├─ ModesRepository             // reminder modes/entries
│   └─ HabitsRepository (NEW)      // habits, records, streak math
├─ reminders/                      // ReminderScheduler, AlarmReceiver, AlarmService, AlarmActivity, SystemEventsReceiver
├─ search/AmharicSearch.kt         // homophone folding + search
└─ ui/
    ├─ theme/ (Theme, Type)        // fixed brand palette, Ethiopic fonts
    ├─ strings/Strings.kt          // interface + AmharicStrings/EnglishStrings + LocalStrings
    ├─ common/AgpeyaBottomBar.kt   // Tab enum + bottom nav
```

## 3. Data Design

### 3.1 Content Models (bundled, read-only)
- `Hour(id, orderIndex, name, transliteration, timeHint, sections)`.
- `Section(id, orderIndex, type, number?, title, subtitle?, reference?, part?, firstVerse, verses)` — `number` set for Psalter entries; `part` labels Midnight watches.
- `Manifest(contentVersion, hours[])`; `Psalter(psalms: List<Section>)`.
- IDs are **permanent contracts** (e.g., `morning_ps62`, `ps_62`); referenced by user data.

### 3.2 User-Data Models (local, JSON-in-DataStore)
- Scalars/enums (SettingsRepository): `ThemeChoice`, `Language`, `ReadingMode`, `AlarmAlert`, `AlarmSound`, font step, keep-screen-on, onboarded.
- `Bookmark(hourId, hourName, sectionId, sectionIndex, title, subtitle?)`; recents `List<String>`; progress `Map<hourId,Int>`.
- Highlights `Map<"sectionId:verseNo", colorKey>`.
- `HourLayout(order, hidden, added)` stored as `Map<hourId, HourLayout>`.
- `HoursConfig(custom: List<CustomHour>, order, hidden, names)`.
- Reminder `PrayerMode`/`ReminderEntry`.
- **`Habit(id, name, isBuiltIn)`** and **`HabitsState(custom, order, hidden, names, records)`** where `records: Map<"yyyy-MM-dd", Set<habitId>>`.

### 3.3 Persistence Strategy
- Each repository owns one Preferences DataStore file (`settings`, `user_data`, `highlights`, `layouts`, `hours`, `prayer_modes`, `habits`).
- Standard idiom: one `stringPreferencesKey("<x>_json")` holding a serialized blob; reads `decode(...) ?: default`; writes via a private `update(context){ it.copy(...) }` transform; `Flow` for observation, `.first()` for one-shot.
- **Forward compatibility**: `Json { ignoreUnknownKeys = true }`; every model field has a default.

### 3.4 Content Pipeline (offline, build-time)
`tools/extract_content.py` emits the prayer-hour assets. `tools/extract_bible_editions.py` bundles Amharic 2000 for the Bible and Amharic/Ge'ez 1980 for Psalms under `assets/content/bible/`. LXX/Ge'ez psalm numbering matches the Agpeya references.

## 4. Component Design (existing modules, brief)

- **Reading** (`ui/reading`) — loads an hour via `HoursRepository.hourById`, applies `PrayerLayout.visible(base + addedPsalms, layout)`, renders vertical `LazyColumn` or horizontal `HorizontalPager` (pages are `LazyColumn`s so verse taps register); verse tap → highlight palette; contents sheet; font/mode/position persistence.
- **Search** (`search/AmharicSearch`) — `fold(text)` maps homophone families to a canonical form preserving vowel order; case-insensitive substring over folded haystacks; returns hour/section/snippet.
- **Personalization** — `LayoutRepository` (+ pure `PrayerLayout`) for per-hour order/hidden/added psalms; `HoursRepository` (+ pure `merge`) for the hour list overlay; `CustomizeHourScreen`/`ManageHoursScreen`; psalm picker searchable by Arabic numeral.
- **Reminders** — `ReminderScheduler` derives alarms from the active mode; `setAlarmClock` with `SecurityException`→inexact fallback; chain pattern computes next occurrence from time+weekday set; `AlarmReceiver` starts `AlarmService` (foreground, ringing) which shows `AlarmActivity` via full-screen intent; snooze via one-shot alarm; `SystemEventsReceiver` reschedules on boot/update/time change.
- **Localization/Theme** — `Strings` interface + two objects + `LocalStrings`; `MainActivity.stringsFor(language)`; fixed indigo/gold palette with purpose-built dark scheme.

## 5. UI / Navigation Design
- **Single Activity + NavHost.** Bottom-nav tabs (state-preserving `switchTab`): Home, Search, Bookmarks, **Streak (NEW)**, Settings. Pushed full-screen routes: `reading/{hourId}?section=`, `modes`, `mode/{modeId}`, `customize`, `customize/{hourId}`, `habits (NEW)`, `about`, `battery`, `intro`.
- **Onboarding gate**: start destination chosen after the `onboarded` flag resolves (avoids a flash of Home).
- **Deep link**: an alarm launches `MainActivity` with an hour extra; a `LaunchedEffect` navigates to that hour **after** the graph is composed.
- **Design language**: cream/parchment + indigo primary + gold secondary; Abyssinica serif for scripture, Noto Sans for chrome; minimal chrome, hairline dividers, generous spacing; theme-adaptive; Amharic/English strings.

## 6. Detailed Design — Habit-Streak Module (NEW)

### 6.1 Overview
Adds a 5th tab presenting: an overall-streak hero, today's habit check-off,
per-habit streaks, and a contribution heatmap; plus a management screen for
habits. No new permissions; local persistence only.

### 6.2 Data & Persistence
- `HabitsRepository` (DataStore `habits`, key `habits_json`) storing `HabitsState`.
- Built-in habit IDs are a constant list `["prayer","church","prostrate","bible"]`; their names come from `Strings` (localized), so no seeding/migration. Custom habits carry a stored name; `names` overrides allow renaming built-ins.
- Daily records: `records["yyyy-MM-dd"] = setOf(habitId…)`.

### 6.3 Repository API
- Observation: `state(context): Flow<HabitsState>`, `current(context)`.
- Mutation (via private `update{}`): `toggle(date, habitId)`, `addCustomHabit(name)`, `renameHabit(id,name)`, `deleteCustomHabit(id)`, `setHidden(id,hidden)`, `setOrder(ids)`.
- Pure merge: `orderedHabitIds(state, includeHidden): List<String>` (built-ins + custom, apply order, filter hidden) — mirrors `HoursRepository.merge`.

### 6.4 Streak & Heatmap Algorithms (pure, unit-tested)
Inputs are `records` and a `today: LocalDate`; keys are `LocalDate.toString()`.
- `dayCount(records, date) = records[date]?.size ?: 0`.
- `currentStreak(records, habitId, today)`:
  1. Set `cursor = today`; if `habitId ∉ records[today]`, set `cursor = today − 1 day` (day-tolerant rule, FR-31).
  2. While `habitId ∈ records[cursor]`: increment count; `cursor -= 1 day`. Return count.
- `longestStreak(records, habitId)`: over the sorted set of dates containing `habitId`, find the longest run of consecutive calendar days.
- `overallCurrentStreak(records, today)`: same as current-streak but the predicate is `dayCount(date) ≥ 1`.
- Heatmap cell **level**: `when(count){0→0; 1→1; 2→2; 3→3; else→4}`.

### 6.5 UI Components
- **`StreakScreen`** (`Tab.STREAK`): `Scaffold` + `AgpeyaBottomBar` + `LazyColumn` —
  (1) title; (2) hero `Surface(primary)` with overall streak; (3) today's check-off rows (circular checkbox bound to `records[today]`, tap → `toggle`, inline per-habit current streak); (4) `HabitHeatmap` card; (5) per-habit current/longest list; (6) "Manage habits →" link → `habits` route. Reads `HabitsRepository.state` + resolves names from `LocalStrings`.
- **`HabitHeatmap`**: builds a 7×~53 grid from `today − 52 weeks` aligned to week start; each cell a ~12 dp rounded `Box`; color = `surfaceVariant` (level 0) then `primary.copy(alpha = 0.30/0.50/0.75/1.0)` (levels 1–4) — opacity ramp adapts to light/dark automatically; `horizontalScroll` auto-scrolled to the end; Less→More legend row.
- **`ManageHabitsScreen`** (`habits` route): near-copy of `ManageHoursScreen` — per-habit hide/reorder/rename/delete (delete only for custom) + "＋ New habit" name dialog; new habit appears immediately in check-off.

### 6.6 Integration Points
- `Tab` enum gains `STREAK("streak", Icons.Outlined.LocalFireDepartment)`; bottom-bar label `when` gains a branch; `MainActivity` gains the two routes.
- `Strings` interface + both language objects gain: `tabStreak`, `streaksTitle`, `habitPrayer/Church/Prostrate/Bible`, `manageHabits`, `newHabit`, `habitNameLabel`, `less`, `more`, and parameterized `currentStreak(n)/longestStreak(n)/daysUnit(n)`.
- Dates via `LocalDate.now()`; counts rendered in Arabic numerals (unbounded; `geezNumeral` caps at 199).

### 6.7 Design Decisions & Alternatives
- **Combined heatmap** (intensity = habits/day) over per-habit heatmaps — closest to the GitHub graph and space-efficient; per-habit streaks provide granularity.
- **Manual check-off** over auto-detecting prayer from reading — unambiguous and privacy-clean.
- **Gregorian day boundaries** — java.time native on API 26; Ethiopian-calendar labels deferred.
- **Absolute count levels (0..4+)** over fraction-of-habits — stable when the habit set changes over time.

## 7. Error Handling & Edge Cases
- Corrupt/absent DataStore blob → decode fails safely to defaults.
- Exact-alarm permission denied → inexact fallback (no crash).
- Deep link before nav graph ready → gated by `ready` flag (fixed regression).
- Content update removing a referenced ID → orphaned bookmarks/added psalms pruned or ignored; no crash.
- Time zone/day change → new day key; streaks recompute from records.

## 8. Build, Deployment & Verification
- Build: set `JAVA_HOME` to Android Studio's JBR; `./gradlew.bat testDebugUnitTest assembleDebug`.
- **Unit tests** (JUnit4, JVM): `AmharicSearchTest` (homophone folding), `ReminderSchedulerTest` (next-occurrence), and **`HabitStreakTest`** (current/longest/overall streak incl. today/yesterday rule, gaps, empty history).
- Manual verification: install debug APK; exercise reading/search/reminders/personalization; on the Streak tab, check habits and confirm the heatmap cell darkens and streaks increment; add/rename/hide/delete habits; force-stop and confirm persistence.
- Release: signed AAB via Play App Signing; Data Safety = "No data collected"; verify merged manifest has no `INTERNET` permission.
